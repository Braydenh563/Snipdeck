# Snipdeck Design Language

> Status: **Accepted** (2026-10-17) · Maturity L1 · Source of truth for UI work. Visual specimen: https://claude.ai/artifact/6YZMjUf2HgmA4rCrfT5jWN
> Tokens: `design/tokens/palette.json` (generated by `design/tools/palette.py`; never hand-edit hex).

## 1. Visual Theme

**Theme statement: _calm, tactile deck_.**

Snipdeck is a deck of index cards at the edge of your screen. The interface is quiet: neutral
card-stock surfaces and one ink-blue accent. Each List has its own colour, shown the way an index-card
divider tab would show it: on the tab, never painted across the cards.
Depth is soft and has only one level, so items read as things you can pick up. The type is
precise and tabular. It should feel like a well-made physical tool, not a dashboard.

**Signature details:** these make it Snipdeck rather than a generic list app.
1. **Number gutter.** Cards are numbered 1–9 in a mono left margin, like a ruled index card.
2. **Ink, not blue, for commitment.** Primary buttons are near-black ink. Blue only ever means *selected, focused, a link, or a template field*.
3. **The deck edge.** When more cards sit below the fold, two offset card edges peek out at the bottom of the list instead of a fade.
4. **Card pull.** Using an item lifts its card slightly, as if you'd pulled it from the deck.
5. **System material (enhancement, not baseline).** On Windows 11 build 22621+ the window chrome may sit on Mica so the panel belongs to the desktop; cards stay opaque card stock on top. The **baseline is solid `bg.app` chrome**, which is what the panel ships if Mica proves unreliable: Mica goes flat grey when its window is inactive, and the panel is never the active window (M0 S4, unverified on Windows).

- **Design read:** Windows-first desktop utility for people who paste a lot · restrained/professional · own brand, Linear/Raycast family.
- **Dials:** Creativity = Balanced · Density = Packed-balanced · Variance = Uniform · Motion = Low.
- **References → traits:**
  - Raycast: keyboard-first, single accent.
  - Linear: hairlines, layered greys.
  - Things 3: calm depth, deliberate micro-motion.
  - Index cards: coloured divider tabs, stack metaphor.
  - Braun: one functional colour, honest materials.
  - Swiss timetables: tabular density.
- **Rejection test:** if a choice makes the panel louder than the app the user is working in, it's wrong.

### List accents (index-card tabs)
Nine curated hues: `blue · teal · green · amber · orange · red · rose · violet · slate`.
Rendered as a **2px underline** on the active list tab, an **8px square mark** in the sidebar, and a
**6px mark + list name** label on items in mixed views (picker, search, Recent). Uses step 600 in light and
step 400 in dark; every one is ≥ 4.2:1 against the surface. Never painted on cards (a full-height left
border on cards is a generic-AI trope, and within one list it repeats the same colour on every card), and
never used as a fill behind text.

### User accent choices
`blue` (default), `teal`, `green`, `orange`, `rose`, `violet`, `slate`. Each maps to the same
600/700/800 steps; the checks run for every option.

## 3. Typography

**Families (bundled, SIL OFL):**
- **IBM Plex Sans** (400/500/600): all UI text. Chosen for its distinctive but neutral letterforms, tabular figures, and wide Latin coverage. It also avoids the generic-AI look of Inter and Geist.
- **IBM Plex Mono** (400/500): code-like snippet previews, keycaps, hotkeys, template placeholders.
- **CJK fallback (system):** `Yu Gothic UI` (ja), `Microsoft YaHei UI` (zh-Hans). On macOS v1.1: Hiragino Sans, PingFang SC.

**Scale:** ~1.125 ratio, base 13px (dense desktop UI). Sizes are scaled by the Windows text-scale and DPI factors, never hard-locked.

| Token | Size | Line height | Weight | Role |
|---|---|---|---|---|
| `type.xs` | 11 | 16 | 400 / 500 mono | keycaps, meta, counts |
| `type.sm` | 12 | 16 | 400 | secondary text, previews, labels |
| `type.base` | 13 | 20 | 400 / 500 | item titles, body, inputs |
| `type.md` | 14 | 20 | 500 | panel header, dialog body emphasis |
| `type.lg` | 16 | 24 | 600 | section headings (main window) |
| `type.xl` | 20 | 28 | 600 | page titles, empty-state headings |
| `type.2xl` | 24 | 32 | 600 | onboarding only |

- Letter-spacing: 0 at body sizes; +0.2px for `xs` uppercase labels (use sparingly); −0.2px at `xl` and up.
- Figures are tabular (`tnum`) wherever numbers align (counts, keycaps, dates).
- Minimum weight is 400. Uppercase only for labels of 3 words or fewer.

### ItemCard anatomy (the most important component)
```
 1 │ Title of the snippet
   │ Preview line one, secondary colour…
   │ Preview line two…                     Paste ↵    ← appears on hover / keyboard focus
```
- **Number gutter:** 24px left margin with the quick-use number (1–9) in `type.xs` mono `text.tertiary`, separated from the content by a 1px `border.subtle` rule. Items 10+ show an empty gutter. The rule is the "index-card margin".
- **Content-aware leading (no generic icons):**

  | Content | Leading element |
  |---|---|
  | Plain text | none: title starts at the rule |
  | Template | `{ }` glyph; placeholders in mono `accent.text` |
  | Code | `</>` glyph; preview in mono |
  | Link | link glyph; preview shows the domain in mono |
  | Image | 56×36 thumbnail, radius 4 |
  | File | file-type glyph + extension |
  | Sensitive | lock glyph; preview `•••• •••• 7f3a` in mono |
- The card has an 8px radius, a `bg.surface` fill and a 1px `border.subtle` border. No coloured edge. In mixed views, a list label (6px mark + name, `type.xs`) sits at the right.
- **Use label:** on hover or keyboard focus a single text button appears at the bottom right: **"Paste ↵"** when a target is known, otherwise **"Copy ↵"**. Ghost style, `type.sm` 500. Everything else (Copy, Edit, Pin, Move, Delete) lives in the context menu (right-click, Menu key, `⋯` in the main window). Shift+click always copies.
- Sensitive items: click-and-hold reveals the content.
- **Card pull (use feedback):** the card lifts 2px to depth level 2 over 140ms, the gutter number becomes a ✓ in `accent.text`, then it settles back over 200ms after 700ms. With reduced motion: no translation, ✓ swap only.
- Links don't fetch favicons: Snipdeck makes no network calls unless the user opts in. The site-icons setting is off by default.

## 5. Layout

- **Base unit: 4px.** Spacing scale: `space.0.5`=2 · `space.1`=4 · `space.2`=8 · `space.3`=12 · `space.4`=16 · `space.5`=20 · `space.6`=24 · `space.8`=32 · `space.12`=48.
- **Radius (locked):** `radius.sm`=4 (keycap, tag, swatch) · `radius.md`=6 (button, input, menu item) · `radius.lg`=8 (ItemCard, popover, dialog). Top-level windows use the OS corner (Win11 DWM round, 8px).
- **Hit targets:** at least 24×24 (WCAG 2.2 target size); default 28.
- **Proximity:** 4px between related parts of a card, 6px between cards (comfortable), 0 with hairline dividers in compact mode, 16px between groups.

### Panel
- Width: default 320, min 260, max 480. Height: free, or full height when docked.
- Header: 40px. Tab bar: 32px. Padding: 8px.
- **Target footer** (32px): "Pastes into **Outlook** · New message". It always shows where a click will go, and reads "Copies to clipboard" when no target is known.
- Docked to an edge it auto-hides to a **6px tab** in the board's accent colour, and reveals on hover after 150ms or by hotkey.
- **Chrome** (header, tab bar, footer): solid `bg.app` baseline. Optional **Mica** enhancement on Windows 11 22621+ (`DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_MAINWINDOW`, software renderer, chrome transparent, cards opaque); it is switched off on Windows 10, with "Transparency effects" off, in high-contrast mode, and for the never-active panel unless the S4 workaround proves reliable. The main window (which is activated normally) is where Mica is expected to look right.
- **DeckEdge:** when the list overflows, the bottom 10px shows two card edges, each 4px tall and inset 6px / 12px per side, in `bg.surface` with a `border.subtle` outline. The top edge shows the same once scrolled. No gradient fades.

### Picker
- 560 wide, up to 9 visible rows plus the search field (44px tall).
- Anchored below the caret. If there's no room, it flips above. If there's no caret, it opens at the mouse.

### Main window (3-pane)
| Zone | Width | Content |
|---|---|---|
| Sidebar | 232 (resizable 200–320), on Mica | Search, Recent, Pinned, Boards ▸ Lists, Tags, Trash |
| Item list | flex, min 320 | toolbar (view, sort, filter) + ItemCards / tiles |
| Detail | 400 (resizable 320–640) | preview, editor, metadata |

## 6. Depth

The Index deck uses **one soft level** plus OS-level floating. Shadows are tinted with the warm neutral, never pure black. In dark mode, depth comes from **tone**, not shadow.

| Level | Light | Dark | Used for |
|---|---|---|---|
| 0 flat | none | none | window background, sidebar |
| 1 card | `0 1px 2px` neutral-850 @ 6% + 1px `border.subtle` | `bg.surface` on `bg.app` + 1px `border.subtle` | ItemCard, inputs |
| 2 lifted | `0 4px 12px` neutral-850 @ 10% | `bg.overlay` + `0 4px 16px` black @ 40% | dragging card, hovered tile |
| 3 floating | OS DWM window shadow + 1px `border.default` | same | Picker, panel, menus, popovers, dialogs |

Layering: window → cards → lifted (drag) → popovers/menus → toasts → capture overlay (topmost, full screen, 40% scrim).

## 7. Do's and Don'ts

### Do
- Reference semantic tokens only. New colours come through `palette.py`, and its contrast checks have to pass.
- Keep **one accent per surface**. List colours appear only as tab underlines, sidebar marks and list labels.
- Design every state: hover, focus (visible 2px ring), pressed, disabled, loading (skeleton), empty (EmptyState with an action), error (inline, plus a toast for transient errors).
- Pair every semantic colour with an icon or label. Hue never carries meaning on its own.
- Write real copy, in plain verbs: "Copy", "Paste", "Save from clipboard", "Extract text".

### Don't
- No glow, gradient text, glassmorphism blur or AI purple. No pure `#000` or `#FFF`. Mica is the only material, and only on chrome.
- No blue primary buttons. Blue means selection, focus, links and template fields.
- No generic leading icons on plain text, and no row of three icon buttons on hover.
- No status dots in front of every item, and no coloured left-border cards. No decorative eyebrows or version badges in the UI.
- Don't mix shadow grammars: no hard offsets, and no heavy shadows in dark mode.
- Never make the panel louder than the user's app: no animated attention-seekers and no badges for unread history.
- No radii outside 4 / 6 / 8, and no font sizes outside the type scale.

| Token | Duration | Easing | Use |
|---|---|---|---|

### Text entry and IME (from M0 S2)
- Composition text is drawn inline as a selection highlight; there is no underline or active-clause marker in Slint 1.18. Accepted for v1.
- Search fields keep the end of a long composition visible (custom field, small `.slint` change).
- Latin text uses IBM Plex Sans; Han/Kana/Hangul fall back in the per-locale order set in code, never left to the system pick.

## 9. Agent Prompt Guide

1. **Tokens only.** Every colour, size, radius, spacing value and duration comes from the `Tokens` Slint global (generated). A literal hex or px value in a `.slint` component is a bug.
2. **Never steal focus.** Panel and picker interactions must preserve the user's target window (ADR-0003). No component may call activate/focus on the panel except text-entry components, and those must restore the target afterwards.
3. **4px grid, 4/6/8 radii, 7 type sizes, IBM Plex only, Phosphor only.** No exceptions without updating this file.
4. **Every interactive element:** 24px or larger hit target, visible focus ring, accessible name (AccessKit), keyboard path, and all five states.
5. **One accent per surface.** List colours only as tab underlines, sidebar marks and mixed-view labels. Semantic colour always paired with an icon or text.
6. **Ink commits, blue selects.** Primary buttons use `ink.*`. `accent.*` is never a button fill.

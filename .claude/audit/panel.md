# Deep audit: panel (Panel, docking, Picker, command palette, paste-into-target, typing expansion)

Head audited: `origin/claude/compassionate-pascal-pod8ux` at `2d8ec99f` (detached, tooltip and scroll work merged).
Agent: `panel`. Read-only: nothing committed, the probe test (`crates/snipdeck-app/tests/probe_panel.rs`) is deleted.
`run` = measured in the Slint test harness or a Rust probe on Linux. `code` = read only. Nothing here was run on
Windows: every Windows-only path is `code` and is listed again in section 3.

**Nothing was driven.** A probe (`probe_panel.rs`: palette top hits for 59 queries, Ctrl+Z in the Symbols search, element boxes at three sizes and three text scales, the lists-in-menu header, 10,000-item Panel load and Picker timings, footer names) was written and queued behind the shared cargo lock. Every finding below is therefore `code`; the rows that most need a run say so, and section 3 lists them.

## 3. Not verified, and what a Windows run must check

Nothing in this audit ran on Windows. A Windows run must confirm:

1. Paste timing on the UI thread (PANEL-13): time from click to the Panel being responsive again for Notepad, Word,
   a browser field, Windows Terminal and an Explorer file list (expected worst case about 2.1 s frozen, then
   "copied instead").
2. `on_foreground_changed` cost (PANEL-14): Alt+Tab quickly between a UWP app, a Chromium app and Explorer with the
   Panel open; watch for UI Automation waits (250 ms + 500 ms bounds) on the UI thread.
3. Footer names (PANEL-15) for Word, Edge, Windows Terminal, Calculator or Settings (UWP, `ApplicationFrameHost.exe`),
   new Outlook, Teams.
4. Typed triggers: on-screen keyboard, voice typing (Win+H), AutoHotkey or a remote-desktop session typing the code
   (PANEL-18); a trigger with an accented letter on a dead-key layout, and a Japanese or Chinese IME session
   (PANEL-19); Caps Lock state read on the hook thread; Backspace right after an expansion (PANEL-16).
5. Trigger erase when the fill form was confirmed after switching to another document of the same app (PANEL-21).
6. `SendInput` with scan code 0 (PANEL-28) into an RDP, Citrix or VMware client window and into a game or
   scan-code-reading app.
7. Start menu, Search and the taskbar as Target (are they offered as "Pastes into"?); a minimised or hidden
   window as Target; an elevated Target (footer must say copy, not paste).
8. Docking: every edge on a 100 %, 150 % and 225 % monitor, mixed-DPI two-monitor setups, a taskbar on the same
   edge, auto-hide taskbar, a full-screen video and a full-screen game, the 6 px tab under touch, a resize grip held
   under an elevated window (`resize_goes_on` comment says Windows then reports every button as up).
9. Picker: clicking a row's Copy or Edit button and the scrollbar must not dismiss the Picker
   (PANEL-25); open time under 80 ms with 10,000 items in a release build.
10. Tooltips on the Panel: pointer moved from a control onto its tooltip (PANEL-33), tooltip on a docked Panel as it
    collapses, tooltip at 260 px width and text scale 2.25.

Not verified on any platform in this audit (a Linux harness run is enough for these): the palette top hit for "trash" and "delete" (PANEL-1); Ctrl+Z in the Symbols search (PANEL-7); the lists-in-menu header with Symbols open (PANEL-9); element boxes, clipping and 24 px targets at 260x240, 320x480 and a large size at text scale 1.0, 1.5 and 2.25 (PANEL-12); Panel load, Picker open and per-key search at 10,000 items, 50 lists, 5 boards, 200 tags (PANEL-24, PANEL-45).
